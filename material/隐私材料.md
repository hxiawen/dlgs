# 隐私材料

[返回索引](../MVP_index.md) | [任务说明](../readme.md)

## 该项在 MVP 上架中的作用

隐私材料是 Chrome Web Store 审核和用户信任的硬门槛。这里说的不是一句“我们重视隐私”，而是：

- privacy policy URL
- Privacy tab 填写内容
- 数据使用说明
- 与真实产品行为一致的对外承诺

## 当前判断 / 当前缺口

当前仓库未见成熟的对外隐私页面或正式材料包。

而实际产品又确实会处理用户数据：

- 读取 ChatGPT 页面中的用户提问文本
- 将会话与轮次保存在本地
- 后续计划里还考虑接入 PostHog + Sentry

所以隐私材料不能后补，它本身就是上架前置条件。

## 需要做的事情

至少要形成三样东西：

1. 一份可上线的 privacy policy
2. 一份 Chrome Web Store Privacy tab 填写稿
3. 一份内部数据清单，防止对外说错

## 注意事项

- 不要写“我们不收集任何数据”，除非真的不读取、不保存、不上传。
- “本地保存”也应该被说明。
- 一旦接入 PostHog / Sentry，供应商名称、数据范围、用途都要更新。
- 如果新增或修改了 `host_permissions`、`content_scripts.matches`，不仅要改代码，还要回头重审 Privacy tab 与权限说明。

## 指南 / 标准 / 要求

隐私政策至少应说明：

- 产品会处理哪些数据
- 数据来自哪里
- 用来做什么
- 存在哪里
- 是否会分享给第三方
- 用户如何清理或联系我们

对 `Dualogues` 当前最关键的说清楚点：

- 核心功能依赖读取用户在 ChatGPT 对话中的提问内容
- 这些内容默认用于本地导航
- 若未来启用统计/错误监控，只能上传最小匿名技术数据，不能上传用户问题文本
- 如果未来为了非核心能力增加权限，优先考虑 optional / runtime permission，而不是直接扩大安装时权限

## 操作步骤

1. 先完成 [数据合规](../封版/数据合规.md) 里的数据清单。
2. 决定隐私政策承载位置：
   - 官网页面
   - 独立帮助站点
3. 写政策初稿，重点写真实行为，不写空话。
4. 写 Privacy tab 草稿：
   - single purpose
   - permission justification
   - remote code
   - data usage
5. 检查 manifest 权限是否与这份材料完全一致，尤其是：
   - `permissions`
   - `host_permissions`
   - `content_scripts.matches`
6. 与最终产品行为逐项核对。
7. 上线政策 URL 后，再回填商店后台。

## 验收标准

- 有真实可访问的 privacy policy URL。
- Privacy tab、隐私政策、代码行为三者一致。
- 新增统计或错误监控后，材料能在同一轮版本中同步更新。
